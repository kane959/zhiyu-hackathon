# 验收操作手册

按顺序执行，每一步写明「在哪台机器、输什么、看到什么算过」。全程不需要判断力，只有阶段 5 需要眼睛。

| 阶段 | 在哪 | 耗时 | 需要谁 | 判据 |
|---|---|---|---|---|
| 0 准备 | 本机 PowerShell | 1 分钟 | 你 | 目录与 Python 正确 |
| 1 代码验收 | 本机 | 5 分钟 | 你 | 30/30 + 53 tests OK |
| 2 本地人工 | 本机 + 浏览器 | 10 分钟 | 你 | 8 项界面检查全过 |
| 3 部署 | 阿里云主机 | 40 分钟 | 等 P 给 IP/域名 | 本机 curl 返回 ok |
| 4 主机验收 | 主机 + 本机 | 20 分钟 | 你 | 30/30 + 十项手工 |
| 5 收尾 | 主机 + 本机 | 5 分钟 | 你 | 数据清干净、三样存证 |

阶段 1、2 现在就能做，和主机无关。阶段 3 之后必须等 P。

## 先分清两种窗口

文档里的命令块分两种，**不能混着敲**：

| 标记 | 在哪 | 长什么样 |
|---|---|---|
| `powershell` 代码块 | 你自己的 Windows 电脑 | `cd D:\湾区S3黑客松`、`Get-Content`、`Remove-Item` |
| `bash` 代码块 | 阿里云主机（Linux） | `cd /srv/zhiyu/app`、`systemctl`、`sqlite3` |

典型的撞墙方式：在 Windows 的 PowerShell 里敲 `cd /srv/zhiyu/app`，报「找不到路径 D:\srv\zhiyu\app」。这个路径长在主机上，本机没有。先 `ssh root@<IP>` 登上去，再敲 bash 块。

阶段 3、4、5 全部在主机上；阶段 0、1、2 全部在本机。

## 阶段 0：准备（1 分钟）

**窗口**：本机，普通权限 PowerShell（不要用管理员）。

### 0.1 进项目目录

```powershell
cd D:\湾区S3黑客松
Get-Location
```

期望输出 `D:\湾区S3黑客松`。若显示 `C:\WINDOWS\system32`，说明没切成功，后面的相对路径全都会报 `No such file or directory`。

### 0.2 确认 Python

```powershell
python -V
```

期望 `Python 3.9` 或更高。报「不是内部或外部命令」就先解决 Python。

### 0.3 确认文件在

```powershell
Get-ChildItem server.py, scripts\accept.py
```

两个文件都要列出。缺任何一个说明目录不对或代码没拉到。

## 阶段 1：代码验收（5 分钟，不碰真实数据）

**窗口**：本机 PowerShell，仍在项目根目录。

### 1.1 黑盒总检（30 项）

```powershell
python scripts\accept.py
```

**期望**（最后三行）：

```
====================================================
通过 30/30，耗时 1.1s
全部通过。
```

紧跟一条确认退出码：

```powershell
echo $LASTEXITCODE
```

期望 `0`。判断只能用它，不要用 `$?`——PowerShell 5.1 对原生程序用 `2>&1` 时，成功也会把 `$?` 置为 False。

**不过怎么办**：失败项会打印 `[失败] 名称 原因`。按 `docs/验收.md` 最后一节的定位表处理，别从头翻。

### 1.2 函数级测试（65 组）

```powershell
python -m unittest -v test_flow test_deploy test_matcher test_publish test_events test_frontend_contract
```

**期望**末两行：

```
Ran 65 tests in 40s
OK
```

**为什么两条都要跑**：`unittest` 测迁移、限流计数、Cookie 属性这类内部行为；`accept.py` 发真请求、带真 Cookie，测「伪造 Host 会不会被拦」。任何一条单跑都可能漏。

### 1.3 存证（可选但建议）

```powershell
python scripts\accept.py | Tee-Object -FilePath docs\accept-20261119.log
echo $LASTEXITCODE
```

产物：`docs\accept-20261119.log`，约 45 行。交作业时要贴这段。

## 阶段 2：本地人工验收（10 分钟）

这一步验的是自动脚本看不见的东西：样式、手机布局、控制台报错。

### 2.1 起一个干净实例（窗口 A）

**新开一个 PowerShell 窗口**，输入：

```powershell
cd D:\湾区S3黑客松
$env:ZHIYU_DB="D:\湾区S3黑客松\var\manual.sqlite3"
$env:ZHIYU_DEMO=1
python server.py --port 4173 --open
```

**期望**：控制台打印一行 `Zhiyu: http://127.0.0.1:4173/ build=...`，浏览器自动打开首页。

**要点**：`ZHIYU_DB` 指向 `manual.sqlite3`，跟真实数据 `var\zhiyu.sqlite3` 隔离，验收怎么折腾都不影响演示数据。`ZHIYU_DEMO=1` 会预置一个带卡片和两条反馈的工作区。

这个窗口**保持运行**，验收结束前不要关。

### 2.2 取演示恢复码

**窗口 B**（再开一个 PowerShell）：

```powershell
cd D:\湾区S3黑客松
Get-Content var\DEMO_CODE
```

**期望**：输出形如 `ZY-4XEM-CUWU` 的一串。记下来，2.4 要用。

### 2.3 首页与工作台

**浏览器**（阶段 2.1 自动打开的那个）访问：

```
http://127.0.0.1:4173/
```

**看三件事**：

- 页面有样式，不是裸 HTML
- 工作台里有「拾句 · 访谈证据摘录」项目，不是空白
- 顶部项目切换、卡片区都点得动

### 2.4 读者卡片页

**做法一（推荐）**：在工作台里点卡片的预览/查看入口，地址栏会变成 `/t/xxxx` 形式。

**做法二（兜底）**：窗口 B 查 slug：

```powershell
python -c "import sqlite3;print(sqlite3.connect(r'D:\湾区S3黑客松\var\manual.sqlite3').execute('select slug from cards').fetchall())"
```

拿到 `('xxxx',)`，浏览器访问 `http://127.0.0.1:4173/t/xxxx`。

**看四件事**：卡片正文正常、试用按钮可点、反馈表单能展开、进度条之类不塌。

### 2.5 恢复页

浏览器访问：

```
http://127.0.0.1:4173/recover
```

**看**：有样式（深色卡片布局，不是裸 HTML）、输入框能打字、按钮可点。

**做**：把 2.2 拿到的码粘进输入框，点「认领」。

**期望**：跳到工作台，能看到同一个项目。

### 2.6 跨浏览器认领

1. A 浏览器打开 `/recover`，点「生成恢复码」，得到新的 `ZY-XXXX-XXXX`
2. B 浏览器（Edge，或 Chrome 无痕窗口）打开 `http://127.0.0.1:4173/recover`
3. B 粘贴新码，点认领

**期望**：B 的工作台里能看到 A 建的项目和卡片。看不见就是隔离没做成，属于 B2-1 的硬指标。

### 2.7 看板计数

工作台切到结果/看板页。

**对照**：演示数据是 `visits=2 opened=2 completed=1 feedback=2`。你在 2.4 里每刷新一次卡片页，访问数应该 +1（同一浏览器同版本去重，刷两次只算一次）。

**不对的常见原因**：换了浏览器或清过 Cookie，`visits` 表按 `(slug, reader)` 去重，会多算一条。不是 bug。

### 2.8 控制台

F12 → Console → 刷新页面（F5）。

**期望**：没有红色报错，没有 `Content Security Policy` 拦截记录。

**为什么必看**：服务端下发了 `script-src 'self'`。谁往 `index.html` 里加了内联 `<script>` 或 `style="..."`，页面会静默失效——样式不生效、按钮没反应，但 HTTP 全是 200。自动测试发现不了。

### 2.9 手机布局

F12 → 设备工具栏（`Ctrl+Shift+M`）→ 选 iPhone SE（375×667）。

**看**：不出现横向滚动条，按钮点得到，卡片正文不挤成一团。

**真机怎么办**：服务进程写死只监听 `127.0.0.1`，手机连不上。真机验收留到阶段 4，用 `https://域名` 打开同一张卡片。

### 2.10 收工

**窗口 A** 按 `Ctrl+C` 停服务。删掉验收库：

```powershell
Remove-Item var\manual.sqlite3*, var\DEMO_CODE -ErrorAction SilentlyContinue
```

## 阶段 3：部署（40 分钟，等 P 给 IP 与域名）

**窗口**：3.1 在本机 PowerShell 敲 `ssh`；登录之后，3.2 起的每个 `bash` 块都在主机上敲。详细命令在 `docs/DEPLOY.md`，这里只列顺序和每步的验证点。

### 3.1 连通

```powershell
ssh root@<主机IP>
```

过不了就是安全组 22 没放行你的 IP。

### 3.2 装依赖

```bash
apt update
apt install -y python3 sqlite3 caddy
adduser --system --group --home /srv/zhiyu zhiyu
mkdir -p /srv/zhiyu/var /srv/zhiyu/backup
chown -R zhiyu:zhiyu /srv/zhiyu
```

验证：`python3 -V` 有输出，`sqlite3 --version` 有输出。

### 3.3 拉代码

```bash
sudo -u zhiyu git clone https://github.com/kane959/zhiyu-hackathon.git /srv/zhiyu/app
cd /srv/zhiyu/app
sudo -u zhiyu git checkout main
git log -1 --format='%h %s'
```

部署主仓 main 上经过验收的提交，并记录完整提交号。

验证：`git log -1` 显示你记录的已验收提交号，部署分支为 `main`。

### 3.4 环境变量

```bash
sudo install -m 600 -o root -g root .env.example /etc/zhiyu.env
sudo nano /etc/zhiyu.env
```

至少改这四行：

```
ZHIYU_HOSTS=localhost,127.0.0.1,你的域名
ZHIYU_PUBLIC_ORIGIN=https://你的域名
ZHIYU_TRUST_PROXY=1
ZHIYU_SECURE_COOKIE=1
```

验证：`sudo cat /etc/zhiyu.env` 能看到四项都改过。

### 3.5 进程托管

```bash
cp deploy/zhiyu.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now zhiyu
systemctl status zhiyu --no-pager
```

验证：`active (running)`。

**必查**：`curl -s http://127.0.0.1:4173/api/health` 返回 `{"ok":true,...}`。返回 503 说明 `ZHIYU_DB` 路径不可写，看 `journalctl -u zhiyu -n 50`。

### 3.6 反向代理

```bash
cp deploy/Caddyfile /etc/caddy/Caddyfile
nano /etc/caddy/Caddyfile   # 改成你的域名
systemctl reload caddy
```

验证：`curl -I https://你的域名` 返回 200，证书主体是你的域名。

## 阶段 4：主机验收（20 分钟）

**前提**：阶段 3 全过。域名只是门牌号，门后没人才会报「这个地址后面不是知遇」。

**窗口**：SSH 登录后的主机终端。`/srv/zhiyu/app` 是主机上的路径，在 Windows 的 PowerShell 里 `cd` 它必然报「找不到路径」。

### 4.1 对公网地址跑同一套检查

```bash
cd /srv/zhiyu/app
python3 scripts/accept.py --base https://你的域名
```

**先把 `你的域名` 换成真实域名**，形如 `python3 scripts/accept.py --base https://zhiyu.abc.com`。占位符、中文域名、缺 `https://` 会被脚本当场拒绝并说明原因，不会跑到一半才失败：

```
域名里含中文：你的域名
这里要填真实的域名，不是文档里的占位符。
```

**期望**：先打印 `目标确认：build=...`，再 `通过 30/30`。

**注意**：这一轮会**真的留下数据**（一个「验收工具」项目、一张卡、一条反馈），5.1 清理。

### 4.2 十项手工（脚本覆盖不到）

| # | 输什么 | 期望 |
|---|---|---|
| 1 | `systemctl is-enabled zhiyu && systemctl is-active zhiyu` | `enabled` / `active` |
| 2 | `ss -lntp`（看 4173 那行） | 只出现 `127.0.0.1:4173`，不是 `0.0.0.0` |
| 3 | `curl -I http://你的域名` | `301` 跳 https |
| 4 | `curl -sI https://你的域名`（看响应头） | 有 `Strict-Transport-Security: max-age=31536000` |
| 5 | `journalctl -u zhiyu -n 50` | 日志里的 IP 是你的公网 IP，不是 `127.0.0.1` |
| 6 | `curl -s https://你的域名/api/health` | `version` 对应 `git rev-parse --short HEAD` |
| 7 | `systemctl restart zhiyu` 后再跑 4.1 | C 组仍能读到重启前建的项目 |
| 8 | `sudo -u zhiyu /srv/zhiyu/app/scripts/backup.sh` | 输出 `backup ok`，`/srv/zhiyu/backup` 有新文件 |
| 9 | `sudo bash scripts/restore-check.sh /srv/zhiyu/backup/<文件>` | 输出 `restore rehearsal ok`，五类记录计数与备份一致 |
| 10 | 两个浏览器各建一个项目 | 互相看不见 |

第 8、9 项是 PDF 里 B2-4 的原话，**必须留输出，不能只说做过**。截图或复制日志都行。

### 4.3 手机真机

手机浏览器打开 `https://你的域名/t/<slug>`（域名换成真实值，`<slug>` 从工作台卡片入口复制）。

**看**：不横向滚动、按钮点得到、反馈能提交。

## 阶段 5：收尾（5 分钟）

### 5.1 清验收数据

**在主机上**先查 id：

```bash
sqlite3 /srv/zhiyu/var/zhiyu.sqlite3 "select id, json_extract(data,'$.name') from projects;"
```

删项目：

```bash
sqlite3 /srv/zhiyu/var/zhiyu.sqlite3 "delete from projects where json_extract(data,'$.name')='验收工具';"
```

再按 pid 删卡片、访问、反馈（`<pid>` 换成上一步查到的 id）：

```bash
sqlite3 /srv/zhiyu/var/zhiyu.sqlite3 \
"delete from visits where slug in (select slug from cards where pid='<pid>');
 delete from feedback where slug in (select slug from cards where pid='<pid>');
 delete from cards where pid='<pid>';"
```

别在演示前忘记，否则看板上会多一个「验收工具」。

### 5.2 存档三样

1. `docs\accept-20261119.log`（那是 27/27 的旧记录；重跑后以新的 30/30 为准，旧文件仅作历史）
2. 4.2 第 8、9 项的备份与恢复输出
3. 手机卡片页 + 跨浏览器认领的截图

三样凑齐，P 不用再问「到底能不能用」。
