# 契约冻结清单 · 11/21 20:00 对齐会

用途：会上逐条过，确认一条打一个勾。会后 `API.md` 按此冻结；谁要改，走文末流程，不私下改字段。

三方的默认预期都是「不改，保持现有行为」。理由：`server.py`、`app.js`、`fixtures.py` 已在同一套字段上跑通 65 组测试和 30 项黑盒验收，改字段的收益要先证明大于返工成本。

## 一、B1 需确认：匹配接缝

已实现 `matcher.py`，`server.py` 只调用 `matcher.run(project, mode)`。B1 替换函数体即可，服务端、前端、测试都不用动。

| # | 条目 | 当前约定 | 确认 |
|---|---|---|---|
| B1-1 | 入参 | `project` 为 dict，键固定 `name, url, material, task, output, limits, audience`；`mode` 取 `synthetic` / `live` | ☐ |
| B1-2 | 出参 | 恰好三键 `status`、`errorCode`、`candidates` | ☐ |
| B1-3 | 状态 | `success`（有命中）/ `empty`（检索成功无命中）/ `failed`（调用失败） | ☐ |
| B1-4 | 错误码 | `not_configured`、`upstream_error`、`rate_limited`、`timeout`，四选一或 `None` | ☐ |
| B1-5 | 候选字段 | `id, title, author, url, sourceType, evidence, judgment, reason, unknown`，九键不多不少 | ☐ |
| B1-6 | 排序 | 最多 3 条，按 `适配 → 待核实 → 排除`；同档内不做二次排序 | ☐ |
| B1-7 | `judgment` 取值 | 仅 `适配`、`待核实`、`排除`。发布只接受 `适配` | ☐ |
| B1-8 | `url` 形态 | 站内路径 `/source/xxx` 或完整外链，前端不再拼接 | ☐ |
| B1-9 | 异常处理 | 失败落在 `status`/`errorCode`，不抛异常（抛了服务端会 500，前端拿不到状态） | ☐ |
| B1-10 | 耗时预算 | 单次 ≤ 10 秒。当前服务端同步调用，没有超时中断 | ☐ |
| B1-11 | 幂等 | 同一 `requestId` 只写一条 `runs`，重复请求返回首次结果，不重新检索 | ☐ |
| B1-12 | 写库归属 | `runs` 由服务端写，`matcher` 不碰数据库 | ☐ |

验证命令：`python -m unittest -v test_matcher`（7 组，专门钉这套契约；B1 换实现后必须仍全绿）。

## 二、F1 需确认：项目与发布

| # | 条目 | 当前约定 | 确认 |
|---|---|---|---|
| F1-1 | 项目字段 | `POST /api/projects` 收 `name, url, material, task, output, audience`，`limits` 可选；返回 `projectId` 加全部字段 | ☐ |
| F1-2 | 更新语义 | 带 `projectId` 为更新，不带为新建；两者都校验 URL 协议，`data:` 之类返回 400 | ☐ |
| F1-3 | 匹配调用 | `POST /api/projects/{id}/runs`，body 为 `{requestId, mode?}`；当前同步返回完整结果，没有轮询 | ☐ |
| F1-4 | 匹配幂等 | 相同 `requestId` 返回同一份结果；`mode` 不一致返回 409，不返回旧结果 | ☐ |
| F1-5 | 发布前置 | 提交 `runId` + `candidateId` + 五个文案字段；`candidateId` 必须是 `适配` 候选，否则 400 | ☐ |
| F1-6 | 项目变更后发布 | 匹配之后改过项目，再发布返回 409，需重新匹配 | ☐ |
| F1-7 | 重复发布 | 内容完全相同则返回原卡片，版本号不升；文案有变化则 `version + 1` | ☐ |
| F1-8 | 卡片字段 | `slug, version, title, material, steps, criterion, question, tool, url, scene, mode` | ☐ |
| F1-9 | 草稿保护 | `runs` 只有项目所有者可读；公开端只暴露已发布卡片 | ☐ |
| F1-10 | 归属校验 | 所有 `/api/projects/{id}/*` 先校验 owner，非本人一律 404（不返回 403，不泄露存在性） | ☐ |
| F1-11 | 运行历史 | `GET /api/projects/{id}/runs` 返回倒序摘要（runId、requestId、mode、status、errorCode、candidateCount、createdAt）；完整候选仍走单条接口 | ☐ |
| F1-12 | 明文访问兜底 | `app.js` 顶部保留 `crypto.randomUUID` 兜底（`getRandomValues` 实现），使 http://IP 下匹配与反馈不崩；补丁必须是外部脚本，不能内联（CSP `script-src 'self'`）；`test_frontend_contract.py` 守卫 | ☑ |

## 三、F2 需确认：公开卡与反馈

| # | 条目 | 当前约定 | 确认 |
|---|---|---|---|
| F2-1 | 公开卡字段 | 同 F1-8；不包含 `owner`、`projectSnapshot`，`mode` 保留用于标注合成/真实 | ☐ |
| F2-2 | 访问事件 | `POST /api/cards/{slug}/visit`，body 仅 `{version}`；同一读者同一版本只计一次 | ☐ |
| F2-3 | 打开事件 | `POST /api/cards/{slug}/open`，`opened` 置 1，重复调用不累加 | ☐ |
| F2-4 | 反馈字段 | `submissionId, status, step, note`；`status` 为 `done`/`blocked`，`blocked` 必须带 `step` 否则 400 | ☐ |
| F2-5 | 反馈幂等 | 同 `submissionId` 只入库一次，重复提交返回同一结果；同一会话换 `submissionId` 再提交返回 409，前端要显示「已提交过」而不是成功（否则读者以为改了、看板还是旧答案） | ☐ |
| F2-6 | 版本校验 | 所有读者写操作带 `version`，与服务端不符返回 409 | ☐ |
| F2-7 | 撤回 | 撤回后公开卡返回 404；已发出的链接一并失效，不做软跳转 | ☐ |
| F2-8 | 结果查询 | `GET /api/projects/{id}/results` 按版本倒序返回 `slug, version, active, publishedAt, visits, opened, completed, feedback[]` | ☐ |
| F2-9 | 计数口径 | `visits` 按 `(slug, 读者会话)` 去重；`opened` 按同一口径；`completed` 只数 `status=done` | ☐ |
| F2-10 | 读者身份 | 存在 HttpOnly Cookie，前端不可读、不下发给开发者列表 | ☐ |
| F2-11 | 多版本并存 | 新版本上线后旧链接仍可打开、反馈仍记在旧版本；只有撤回才让某个链接失效。看板需按 `active` 区分 | ☐ |

## 四、改字段的代价（供会上判断）

| 改动 | 影响面 |
|---|---|
| 候选对象增删字段 | `matcher.py`、`test_matcher.py`、`app.js` 的渲染、`accept.py` C 组 |
| 卡片字段变更 | `server.py` 发布与公开读、`app.js` 两处渲染、`accept.py` C 组 |
| 事件字段变更 | `server.py` 三个事件路由、`app.js` 埋点、`accept.py` D 组、`test_flow` 计数断言 |
| 新增状态或错误码 | `matcher.py` 枚举、`test_matcher.py`、前端状态分支、`API.md` |

改动本身不难，难在四处要同步。所以默认冻结，确有需要就在会上定，会后由 B2 开新 PR 统一改，不留口头约定。

## 五、冻结之后的流程

1. `API.md` 标 v2，字段以本清单为准。
2. 谁要改，先说清「改哪个字段、为什么现有字段不够」，由 B2 评估影响面。
3. 改动进独立 PR，标题带 `契约变更`，合并前必须跑通 `test_flow`、`test_deploy`、`test_matcher` 和 `scripts/accept.py`。
4. 口头同意不算，改完文档才算。

## 六、会上需要当场定的一件事

`mode` 字段在真实检索接入后怎么标注。当前 `synthetic` / `live` 二值；如果 B1 的真实结果里混有合成样例，需要第三态或加 `sourceType` 说明。**这是唯一一处我认为可能需要动契约的地方**，请 B1 在会上给结论。
